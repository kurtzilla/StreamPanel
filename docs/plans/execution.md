## Panel top rail & multi-monitor (`panel-top-rail-multi-monitor`)

Design goals from product feedback:

1. **No accidental full-span width** — restored geometry and layout flush must not use “entire virtual desktop” as the effective max width when that makes the panel look fullscreen; cap silly saved widths; per-monitor work-area clamping.
2. **Top of work area** — panel sits on the top usable edge (above taskbar where applicable), not floating mid-screen by default.
3. **Display switcher** — small control at the **far left** of the title strip (above everything else in the shell) to jump to a chosen monitor (still useful for teleporting without dragging across).
4. **Drag along the top rail** — dragging the existing “drag here to move” region behaves like a **toolbar rail**: `y` pinned to the active monitor’s work-area top while `x` follows the cursor; when the window’s reference point (e.g. center) crosses into another monitor’s horizontal span, **switch active monitor** and snap `y` to that monitor’s work top so the user can **slide along the top and hop displays** without leaving the strip.

Implementation sketch: Win32 `EnumDisplayMonitors` + `MONITORINFO` work rect; sort monitors by `rcWork.left` for predictable order. Reuse in [`app.py`](../../src/streampanel/app.py) `flush_layout_and_persist` for `max_w`/`vroot` or pass per-monitor bounds from the monitor that contains `(x + w//2, y + h//2)`. Refactor [`_bind_drag_region`](../../src/streampanel/window_chrome.py) to accept a callback or move drag logic into `app.py` so it can call monitor helpers (keeps `window_chrome` free of ctypes if preferred).
